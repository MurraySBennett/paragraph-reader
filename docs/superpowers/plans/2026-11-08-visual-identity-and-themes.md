# Visual Identity and Themes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the approved After Hours layout and site-wide theme presets, including three institution palettes, without changing document or teaching-link behavior.

**Architecture:** Keep the current DOM and `data-theme`/CSS token system. Centralize preset IDs and labels for UI and preference validation; put visual tokens in CSS. Restyle existing elements rather than duplicating views.

**Tech Stack:** Static HTML, CSS, vanilla JavaScript, Node tests, Playwright, existing build script.

**Spec:** `docs/superpowers/specs/2026-11-08-visual-identity-and-themes-design.md`

## Global Constraints

- No logos, proprietary fonts, new dependencies, or remote assets. Keep offline release complete.
- New users get After Hours and `sans-system`; saved theme/font choices remain valid.
- No theme in URLs or document records. Keep current import, notes, export, word mode, and keyboard behavior.
- Apply tokens site-wide; keep high contrast, custom colors, and user reading-font options.

## Review Focus

- Old saved `system` preference must remain `system`; a fresh browser must start in After Hours.
- Backup restore must accept each new theme and reject an unknown theme.
- Home appearance control must work before any document is opened.
- Theme palette must reach word mode and dialogs, not just the home screen.
- Narrow screen must keep import actions and reader/notes controls reachable.
